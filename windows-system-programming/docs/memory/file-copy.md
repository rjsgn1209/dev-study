# 파일 복사

## 동기 입출력

일반적인 파일입출력 함수는 동기 입출력 방식이다.
  
합수 리턴 종료 시 파일 입출력이 끝난다.

## 비동기 입출력

비동기 입출력 = 충접된 입출력(윈도우즈에서는 비슷한 의미로 사용된다)
  
중첩된 입출력 이란 입출력 요청 묶음을 운영체제에 전달하여 운영체제가 비동기적으로 처리하는 방식을 의미한다.
  
메모리는 최초 할당된 크기 만큼만 사용하게 되지만 파일은 최초 생성 시 사이즈는 0이고 이후 Write 시 마다 추가적인 메모리를 사용하게된다.
  
파일은 Stream 형태이므로 1열로 저장되는데 파일 입출력 요청 시 파일의 기준점 기준 특정 Offset값 만큼의 위치에 값을 입력하게된다.


## 비동기 입출력 처리 과정

중첩되어 여러 입출력 요청이 동시에 순차적으로 들어오게되었을때 
  
메모리 Offset 값이 큰 요청의 경우 메모리 확보 시간이 필요로해 
  
들어온 순서가 아닌 메모리 확보된 순서에 따라 먼저 입출력 요청을 처리하게된다.

## 비동기 입출력 처리 방식

- Event 방식
- Callback 방식

### Event 방식

중첩된 입출력을 처리 후 SetEvent 하게되면 Wait 하던 스레드에서 Event를 감지하여 동작하게된다.


### Callback 방식

WriteFileEx 함수를 통해 Callback 함수를 원형에 맞춰 등록하게되면 요청되어진 입출력이 끝나고 
  
해당 스레드에서 SleepEx 함수의 두번째 매개변수가 True로 선언 되었을때
  
스레드의 상태가 Alertable Wait 상태가되고 등록된 Callback 함수를 처리하게 된다.

## IOCP

스레드에서 동적 할당 한 메모리를 등록된 완료 Callback 함수를 통해 해제 하게되는 구조를 많이 사용하는데
  
해당 방식으로 IOCP 라고 한다.
