# 스레드 동기화

## 기본이론 
  
프로세스는 하나의 가상 메모리를 가지고있고 스레드는 그러한 가상메모리 공간을 공유하고있다.
  
공유되고 있는 자원들을 여러 스레드에서 동시 접근하게 되면 문제가 발생하게된다.
  
그렇기에 멀티 스레딩 환경 개별을 위해서는 스레드 동기화 기업을 학습해야한다.
  
화장실에 비유하자면 한 사람이 화장실에 들어갔을때 문을 잠그지 않으면 다른 사람이 들어올수 있는 곤란한 상황이 발생한다.
  
그렇기에 한사람이 화장실을 쓰는 동안은 문을 잠궈야한다(Lock)
  
그럼 다른사람이 잠긴 문을 보고 앞에서 기다리게 되고(Wait)
  
화장실에서 볼일을 끝내고 문을 열고 나오면 기다리던 사람이 화장실을 사용하게된다(Unlock)
  
## 동기화 기법

- Critical section
- Mutex, Semaphore
- Event(Set/Reset)

동기화 기법에는 임계영역 동기화, 시점 동기화가 있다.
  
스레드에서 특정 시점을 다른 스레드에 알리고싶다면 Event 객체를 사용하여 시점 동기화를 하게된다.
  
Linked List 자료 구조 형태의 값을 여러 스레드에서 한번에 RWD 반복하게되면 메모리 에러가 발생하게 되는데 
이 같은 경우에 필요한게 임계구간 동기화 이며 사용되게 되는 객체는 일반적으로 Critical section이다.

Mutex, Semaphore, Event는 Kernel Object이고 Critical section 유저영역 동기화 객체이다.
  
Mutex는 Kernel Object이기에 운영체제 레벨에서 관리되는것임으로 부하가 많이 발생하므로 
일반적으로 동시화 시 Critical section쓰는것이 더 효율 적이고 Mutex는 프로세스간의 동기화 시 주로 사용된다.
  
Semaphore 또한 Kernel Object 임으로 부하가 많이 발생하지만 
기능 상 여러스레드 중 n개의 스레드만 접근할수 있도록 하는 기능을 제공하기에 필요에 의해 사용하게된다.
