# 가상메모리공간(VMS)

## 메모리 할당

malloc(), new 사용 시 메모리를 동적 할당하게 되는데 해당 메모리를 힙 구조로 관리하는 추제가 존재하게된다.
  
512byte 할당 시 에도 기본적으로 1MB가 할당되게 된다.
  
이후 1MB를 초과하지 않으며 계속해서 할당되어있는 1MB내부에서 메모리를 사용하게되고 그렇기에 빠르다.
  
대용량 메모리(1MB 이상) 시 VirtualAlloc을 사용한다.
  
## 가상메모리 공간
  
가상메모리는 유저모드 파티션과 커널모드 파티션으로 나누어진다.
  
가상메모리공간(VMS)는 프로세스 끼리 서로 접근이 불가능하다.
  
가상메모리공간을 사용하기 위해서는 예약과 할당을해야하는데
  
윈도우즈에서 가상메모리 공간을 예약 시에는 64KB 단위로 관리 되며 그렇게 예약된 메모리를 실제 사용(할당) 시 4KB 페이지 단위로 잘라서 사용하게된다.
  
예약된 메모리 공간을 사용하려면 반드시 실제 물리 메모리 영역을 매핑해야 하며 이를 '물리 메모리를 Commit(확정)한다' 라고 표현한다
  
CPU가 접근하려는 가상 메모리 페이지가 물리 메모리(RAM)에 존재하지 않을 때 즉 매핑 하지 않았을때 발생하는데 예외 상황을 Page Fault라고한다.
  
## User mode 파티션

실행파일(.exe, dll) 모듈의 기계어가 로드되는 메모리 공간이다.
  
각 프로세스 마다 독립성이 보장되고 각종 데이터 영역 메모리(Stack, Heap등)가 위치하는 가용 공간이다.
  
가용공간은 실제 물리 메모리에 할당 되지 않는 상태로 존재하다 필요에 의해 커밋되어 사용된다.
  
## Kernel mode 파티션

가상메모리공간에서 x32 운영체제 4GB 메모리 중 뒤의 2GB 공간이며 OS를 구성하는 코드들이 위치한다.
  
해당 영역은 모든 프로세스가 공유하며 User mode 응용 프로그램은 절대 접근할수 없다

## 힙 메모리 영역

프로세스 실행 시 OS는 프로세스 주고 공간에 기본적으로 1MB의 힙 영역을 생성하게된다.
  
힙이라고 하는것은 힙 구조를 관리하는 주체를 의미하게되는데
  
해당 힙은 Queue에 의해 들어오는 할당 작업들을 처리하게된다.
  
멀티 스레딩 환경에서 여러 스레드가 메모리를 할당 하게 되었을 때 성능을 최적화 하기위해 힙을 여러개 생성할수있다.

## 힙 분리 이유

- 효율적인 메모리 관리(단편화 방지)  
- 지역접인 접근  
- 스레드 동기화 비용 회피
